# `control/` — 제어 루프

```
control/
├── loop.py      정해진 주기로 한 사이클씩 돌림
└── motions.py   매 주기 무엇을 시킬지 정함
```

---

## 둘을 나눔

**루프는 무엇을 시킬지 모름.** 주기와 안전만 봄.

```
loop.py      주기, 모드, 시작·종료 순서, 밀림 측정
motions.py   (시간, 관찰) -> 관절 목표
```

같은 루프로 유지·계단·사인파·보행 궤적을 다 돌릴 수 있고, **동작은 하드웨어 없이
시험됨** — 순수 함수라 그냥 부르면 됨.

---

## `loop.py`

### 한 사이클

```
1  목표를 정함        Motion 이 냄
2  계산               로봇이 관절 -> 모터 -> 프레임으로 풂
3  전송
4  수거               상태 갱신
5  기록               텔레메트리
6  다음 주기까지 기다림
```

### 두 가지 모드

| | 하는 일 |
|---|---|
| `OBSERVE` | 들어갈 때 **토크를 끊고** 상태만 읽음 |
| `CONTROL` | 토크를 넣고 명령을 보냄 |

`OBSERVE` 가 토크를 끊는 것은 **하드 안전장치**임. 설정이 잘못돼 있어도 다리가 안
움직이게 함 — 관찰하려고 켰는데 움직이면 안 됨.

동작을 넘겨도 **`OBSERVE` 는 무시함.**

### 관찰 모드도 통신을 함

MIT 프로토콜에는 **읽기 전용 명령이 없음.** 아무것도 보내지 않으면 아무것도 오지
않음.

그래서 `OBSERVE` 는 `robot.refresh()` 를 부름 — 게인과 토크가 0인 명령을 보내고
그 응답을 받음. 토크가 0이라 아무 일도 일어나지 않음.

### 실제 주기를 잼

목표 주기와 실제 주기는 다름. 계산이 길어지거나 수거가 늦어지면 밀림.

**두 가지를 따로 봄.**

| | 무엇을 잡나 |
|---|---|
| `overruns` | 튀는 주기. 목표의 1.5배를 넘긴 횟수 |
| `kept_up` | **꾸준히 느린 것.** 평균이 목표의 90% 미만 |

둘이 다름 — 매 주기 24%씩 넘으면 **한 번도 "밀림" 으로 세지 않으면서** 주파수만
떨어짐. 그것을 `kept_up` 이 잡음.

```
51주기 0.6초 (평균 84.8Hz / 목표 100Hz), 밀림 0회, 최악 12.5ms,
무응답 주기 5회  ** 주기를 못 지킴 **
```

**게인을 만지기 전에 이것부터 볼 것.** 주기가 밀리는데 게인을 튜닝하면 게인이
아니라 주기가 문제인데 게인을 계속 만지게 됨.

`loop_dt` 는 매 주기 텔레메트리로도 나감.

### 밀려도 따라잡지 않음

늦은 만큼 다음 주기를 줄여 따라잡으면 **그 주기가 더 짧아져 계산이 또 밀림.**
한 주기를 늦게 시작하고 마는 편이 나음.

### 멈출 때

```
1  게인을 유지한 채 현재 자세를 목표로 (hold) — 5주기
2  토크 차단
3  텔레메트리 flush
```

**바로 토크를 끊지 않음.** 서 있는 다리에서 힘이 갑자기 빠지면 주저앉음.

**끝나는 경로가 하나임.** 정상 종료든 예외든 `finally` 를 지나며 이 순서를 탐.
자세 유지가 실패해도 토크는 반드시 끊음.

### 한 걸음씩

```python
loop.step(motion, t=0.0)     # 기다리지 않음
```

한 사이클만 떼어 시험하거나 대화형으로 돌릴 때 씀.

## `motions.py`

전부 **함수를 만드는 함수**임. 하드웨어도 CAN 도 모름.

```python
(경과 시간 초, 지금 관찰) -> {관절 이름: 목표 각도}  또는  None
```

`None` 을 내면 그 주기는 명령을 보내지 않음.

| | 무엇 |
|---|---|
| `hold(targets)` | 정해진 자세를 계속 보냄 |
| `freeze(joints)` | **첫 주기의 실측 위치**를 잡고 유지 |
| `step(joint, ...)` | 정해진 시각에 목표를 한 번에 옮김 |
| `sine(joint, ...)` | 왕복 |
| `ramp(joint, ...)` | 정해진 시간에 걸쳐 천천히 |
| `chain((m, 초), ...)` | 순서대로 이음 |

### `freeze` 가 따로 있는 이유

`hold` 는 목표를 미리 정하지만 `freeze` 는 **다리가 지금 있는 자리**를 씀.

목표를 0으로 잡고 제어를 시작하면 토크를 넣는 순간 다리가 0을 향해 한 번에
움직임. 제어 시작 직후 첫 동작으로 씀.

### `chain` 은 각 구간의 0초부터 셈

```python
motions.chain(
    (motions.ramp("knee", start=0.0, end=30.0, seconds=2.0), 2.0),
    (motions.sine("knee", center=30.0, amplitude=5.0, hz=0.5), 10.0),
)
```

이어 붙일 때마다 시간 계산을 다시 하지 않아도 됨. 마지막이 끝나면 `None` 을 냄.

## 게인 튜닝

### 순서

```
1  loop_dt 부터 확인      주기를 못 지키면 게인 문제가 아님
2  hold 로 시작           자세가 유지되나, 처지나, 떨리나
3  step 으로 계단 응답     여기서 대부분이 결정됨
4  sine 으로 확인          추종 지연과 진폭 감쇠
```

### 계단 응답에서 읽는 것

```python
motions.step("knee", start=0.0, end=30.0, at_s=1.0)
```

| 그래프 | 뜻 | 할 것 |
|---|---|---|
| 목표까지 못 감 | `kp` 부족 | `kp` 올림 |
| 지나쳤다 돌아옴 | `kd` 부족 | `kd` 올림 |
| 부르르 떨림 | `kp` 과함 | `kp` 내림 |
| 느리게 도달 | 여유 있음 | `kp` 올릴 수 있음 |

**계단 직전이 평평해야 오버슛을 읽을 수 있음.** `at_s` 로 여유를 두는 이유임 —
시작하자마자 뛰면 초기 과도상태와 섞임.

### 계단이 그대로 안 나감

**점프 가드가 자름.** 한 주기에 `max_delta_deg` 까지만 가므로 실제로는 몇 주기에
걸쳐 올라감. 그 기울기가 속도 상한임.

`right_leg/guard/clip_jump` 가 오르는 것으로 확인됨. 계단 응답을 제대로 보려면
`max_delta_deg` 를 충분히 크게 두거나, `ramp` 로 대신할 것.

### 토크가 상한에 붙었는지

`tau` 가 모터 상한(RS02 17 N·m, RS00 14 N·m)에 붙어 있으면 **`kp` 를 올려도
소용없음.** 이미 낼 수 있는 힘을 다 내고 있음.

기구를 바꾸거나 목표를 낮춰야 함.

### 한 관절씩

```python
motions.step("knee", start=0.0, end=30.0, hold_others={"hipz": -50.0})
```

나머지는 붙잡아 둠. 여럿을 같이 흔들면 **어느 관절이 원인인지 섞임.**

## 쓰는 법

```python
from huphy.control import ControlLoop, Mode, motions

loop = ControlLoop(leg, hz=robot_config.limb("right_leg").control_hz,
                   telemetry=tm, mode=Mode.CONTROL)

motion = motions.chain(
    (motions.freeze(["knee"]), 0.5),                              # 지금 자리를 잡고
    (motions.step("knee", start=0.0, end=30.0, at_s=0.5), 3.0),   # 계단
)
stats = loop.run(motion, duration_s=4.0)
print(stats.summary())
```

`stop()` 으로 다른 스레드나 시그널 처리기에서 멈출 수 있음.

```bash
PYTHONPATH=src python3 -m pytest tests/test_control.py -q
```

40개. 동작은 순수 함수라 그냥 부름. 루프는 가짜 로봇으로 **순서와 안전**을 봄.

고정하는 것:

```
OBSERVE 가 토크를 끊고 시작함
OBSERVE 도 refresh 로 읽음
CONTROL 이 send 다음에 collect
멈출 때 hold 후 토크 차단
예외로 빠져나가도 토크가 끊김
자세 유지가 실패해도 토크는 끊김
텔레메트리 실패가 루프를 멈추지 않음
kept_up 이 꾸준한 느림을 잡음
```

**실제 주기 정밀도는 여기서 확인되지 않음.** `time.sleep` 의 정밀도에 달려 있고,
실물의 부하와도 다름 — `loop_dt` 를 파이에서 직접 봐야 함.
